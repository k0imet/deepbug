- All Python sources compile.
- Test baseline was zero discoverable tests; five focused regression tests now pass.
- Existing uncommitted work was preserved and reviewed as the working baseline.

## Fixed in this pass

### JavaScript collection

1. Replaced attribute-order/quote-sensitive HTML regex collection with tolerant
   HTML parsing. Unquoted `src`, reordered attributes, multi-token `rel`, module
   preloads, classic preloads, inline scripts, and `<base>` URLs are covered.
2. Iframe URLs are no longer misclassified as JavaScript. Embedded application
   shells are fetched as HTML and their bundles are collected one level deep.
3. Empty JS result tables are persisted after a completed run so a clean rerun
   clears stale prior findings rather than presenting them as current.

### Dependency confusion

1. Replaced the UI-exposed no-op implementation that always returned a clean
   result.
2. Added static npm-name extraction from `require`, `import ... from`, and
   webpack `node_modules` paths.
3. Registry checks only report a candidate on a definitive 404. Timeouts,
   throttling, server errors, and unexpected responses are not converted into
   false findings or cached as missing packages.
4. Findings explicitly require confirmation that the package is private and
   that registry/proxy resolution is unsafe. No exploit or package publication
   is attempted.

## Historical project coverage

`projects/mtn` contains three JSON result groups and **no saved JS result
groups**. Newer campaigns contain as many as 20 JS result groups. This means the
existing MTN folder cannot demonstrate that the current JS pipeline covered the
program; it must be rerun from current live hosts and in-scope application entry
points. Historical output should not be silently treated as equivalent to a
current scan.

Other projects with no saved JS result groups: `2GO`, `AirIQ`, `Safaricom`,
`BITOASIS`, `cirtymesh`, `lululemon.com`, `siilo`, and `single-demo`. A zero here
means “no artifact,” not “no issue.”

## Important open work

1. Add end-to-end fixture campaigns that exercise redirects, iframe shells,
   source maps, webpack chunks, inline scripts, and result persistence together.
2. Record run metadata (tool version, configuration hash, start/end time,
   completion state, seed count, and coverage failures). Without it, historical
   campaign output cannot prove completeness.
3. Make every scanner return a structured completion status. Empty findings and
   failed execution must never share the same representation.
4. Continue converting the open findings in `docs/CODE_AUDIT.md` into regression
   tests. Several validator correctness issues remain documented there.
5. Add Next.js build-manifest and server-action inventory as explicit JS result
   types. Generic chunk parsing alone does not establish server-action coverage.
6. Add source-map evidence rows independently of endpoint classification. A map
   fetch outcome and its unpacked source count should be reportable even when it
   yields no endpoint.

Status after the 2026-08-26 JS hardening round:

- Item 1: **DONE** for the JS chain — `tests/test_e2e_fixture.py` runs a local
  ephemeral-port fixture covering seed HTML → iframe shell → main bundle →
  Next.js build manifest → lazy chunk → sourceMappingURL → sourcesContent
  recovery, asserting every stage in `js_coverage` and that no out-of-scope URL
  is fetched. Redirects and non-JS persistence remain open.
- Item 2: **DONE** for JS analysis — `scripts/rerun_js_analysis.py` now writes a
  `ScanRunRecorder` ledger (`run_type=js_analysis`) with per-step statuses,
  per-frame result counts, coverage failures, config hash only, and final
  status completed/partial/timed_out/failed.
- Item 5: **DONE** — proactive Next.js manifest discovery (buildId from HTML /
  inline `__NEXT_DATA__` / `/_next/static/<id>` refs; `_buildManifest`,
  `_ssgManifest`, `_middlewareManifest`, `_routesManifest` candidates are
  scope-gated, capped, and every candidate outcome lands in `js_coverage`;
  `/_next/server/*` is fetched only when directly referenced), plus an extended
  App Router / flight / server-action inventory (`createServerReference`
  variants, `registerServerReference`, `Next-Action` header captures,
  `__next_internal_action_entry_do_not_use__` maps including source-map
  variants, decoded `self.__next_f.push` flight payloads) persisted to
  `js_nextjs_artifacts` with dedup across bundles/chunks/maps/flight. Action
  IDs are recorded as architecture evidence (severity INFO) — never as
  vulnerability claims.
- Item 6: **DONE** — `js_source_maps` carries fetch outcome, status, size,
  sources_count, sources_content_count per map; guessed `{bundle}.map` 404s are
  visible but do not degrade run status.

Also added in the same round: Vite/Rollup coverage — runtime detection,
literal dynamic imports, `__vite__mapDeps`/preload dependency arrays, bounded
`.vite/manifest.json` probing (referenced or strong evidence only), manifest
entry parsing feeding JS chunks through the full analyzer while CSS/images are
recorded but never analyzed as JavaScript.
